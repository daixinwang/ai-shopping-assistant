# 真实模型端到端验收记录

测试日期：2026-09-16（北京时间）。

## 测试目标

本轮测试不以“接口返回 HTTP 200”作为成功标准，而是使用真实模型和本机 FastAPI 服务，验证以下链路：

- Agent 能否把真实用户表达路由到预期工具；
- 多轮会话能否保持商品指代、预算和筛选上下文；
- 返回商品是否真实存在于仓库的 100 条演示商品目录；
- 商品标题、展示价格和预算约束是否与商品 JSON 一致；
- 空输入、空结果和非购物请求是否按约定处理；
- 图片请求能否完成识别、检索和 SSE 输出。

本轮是开发者本地小样本验收，不是独立测试集、生产压测或真实用户实验。

## 运行环境

- 后端：本机 FastAPI，通过 `/chat` 和 `/chat/stream` 发起真实 HTTP 请求；
- 模型：火山 Agent Plan，路由别名 `ark-code-latest`；
- 商品事实库：仓库内 100 条演示商品 JSON；
- 测试脚本：[`backend/eval/live_acceptance.py`](../../../backend/eval/live_acceptance.py)；
- 自动核验器：[`backend/eval/verify_live_acceptance.py`](../../../backend/eval/verify_live_acceptance.py)；
- 原始证据：本目录中的请求、响应、trace、SSE 和耗时 JSON；
- API Key 未写入任何证据文件。

## 自动核验结果

核验器读取原始响应并与仓库商品 JSON 逐项比对，结果保存在 [`verified-metrics.json`](verified-metrics.json)：

- 9 条有效文本场景的预期路由与实际路由一致：**9/9**；
- 4 个非空推荐/筛选响应共返回 11 次商品卡片：**11/11** 通过商品 ID、标题、SKU 价格和预算约束检查；
- 空输入返回 HTTP 400：**通过**；
- 9 条文本链路未记录 `router_error`、`tool_error` 或 `composer_error`：**0 次**；
- 文本端到端耗时：最小 **1.750 秒**、中位数 **10.061 秒**、最大 **29.994 秒**；
- 图片请求 HTTP 200 且收到 SSE `done` 事件，链路耗时 **16.914 秒**；该项只证明链路完成，不证明推荐相关。

离线回归同时复测：后端 **327 passed、7 skipped**，移动端 **13 passed**，TypeScript 类型检查通过。离线测试与真实模型验收是两套不同证据，不能合并为同一准确率指标。

## 未通过项

1. **图片召回相关性**：模型正确识别为蓝色牛仔短裙，但检索返回 T 恤、运动裤和卫衣；服务日志显示视觉重排失败后使用了纯文本排序。图片链路可运行，但“以图搜同类商品”不能宣称通过。
2. **对比字段完整性**：商品指代正确，但核心功效、关键成分、适用肤质和容量规格仍显示为“—”，且没有形成推荐结论；服务日志显示本地 comparison index 尚未构建。
3. **详情证据降级**：详情路由与商品指代正确，但服务日志显示 RAG 证据检索失败后回退到商品目录，不能据此宣称 RAG 详情链路已通过。
4. **生成文案证据约束**：部分推荐文案使用“油皮也友好”“敏感肌更安心”等强表述，尚未逐句建立商品证据映射。
5. **长尾延迟**：品牌排除场景达到 29.994 秒，已经接近移动端 30 秒超时阈值；真实调用中出现供应商客户端重试，当前样本不足以计算稳定 P95。
6. 尚未完成真实购物车全流程、并发、长时间稳定性、模型成本和线上部署验收。

## 复现命令

先在 `backend` 目录启动后端，再从仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe backend\eval\live_acceptance.py `
  --output docs\validation\next-run `
  --image dataset\myntradataset\images\10001.jpg

.\.venv\Scripts\python.exe backend\eval\verify_live_acceptance.py `
  docs\validation\next-run
```

真实验收需要本机已经保存有效模型配置，会消耗少量模型额度。每次应使用新输出目录，避免覆盖历史证据。
