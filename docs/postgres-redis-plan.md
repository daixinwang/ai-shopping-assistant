# PostgreSQL + Redis 工程迁移计划

日期：2026-11-16。范围：在保留离线演示兼容性的同时，交付可运行、可测试的共享存储部署模式。

## 架构与契约

- DATABASE_URL 启用 PostgreSQL：商品、SKU、偏好、会话检查点、幂等记录为持久事实；pgvector 存向量，通过 SQL 同时执行商品和 SKU 硬过滤。
- REDIS_URL 启用共享会话与缓存：最近 10 条消息（不是 10 轮）、工作记忆、带租约的会话互斥、精确键查询向量/召回缓存。重要状态仍可从 PostgreSQL 检查点恢复。
- 默认无数据库配置时保留 SQLite 测试/演示，不自动把 PostgreSQL 故障切换为本地 SQLite。
- 同一会话串行，不同会话并行；租约失效后拒绝状态覆盖。缓存可回源，会话协调不可用时返回明确失败。
- 数据更新递增版本，检索缓存键包含过滤条件、Embedding 模型和数据版本。过期向量不参与检索。
- PostgreSQL 连接池有上限；模型等待期间不持有普通业务事务。购物车变更与幂等成功记录在同一短事务提交。
- 共享部署使用统一环境模型配置；本机配置修改接口和依赖本地数据的旧识图接口需明确隔离，不能被称作共享服务能力。

## 测试口径

- 服务集成必须使用真实 PostgreSQL/pgvector 与 Redis；模型可用确定性 Demo Adapter 隔离供应商成本，报告不得算作真实模型质量评测。
- HTTP 双实例交替访问同一会话，并测试同会话重入、重试加车、Redis 缓存清空后的恢复。
- 真实向量算子使用小型确定性向量检查排序、SKU 过滤与版本一致性；不把此结果称为真实语义召回率。
- 负载测试记录样本量、并发、耗时、错误、P50/P95/P99、环境与模型模式；不预先承诺百万并发。
- 保留原数据，不自动重置用户数据库；测试仅操作专用 Docker 容器与测试数据库。
